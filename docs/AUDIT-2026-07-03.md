## Part 1 - Confirmed bugs, ranked by user-facing impact

### 1. VHF aurora verdict has no latitude gate
`src/derive/conditions.js:1015` → `src/physics/snr.js:596-617`

`snrMarginVhfAurora` gates only on `hpGw < 30`. `bandOpts` carries
`cgmLatAbsValue` but the function never reads it. Worked number at 6 m,
defaults (100 W, 0 dBi, 1500 km): margin ≈ **+19 dB → "excellent · aurora-E"**
for a QTH in Mexico City or Singapore on any day with HP ≥ 30–50 GW (common at
Kp 3–4). The HF side (`lAuroralDb`) has the CGM ramp; the VHF verdict is the
only consumer without it.
**Fix:** gate/taper on QTH CGM latitude with the same Kp-expanded threshold
`cgmThreshold = 60 − 10·min(1,(kp−5)/2)`, ramping to zero ~10° equatorward.

### 2. One malformed Kp-history row NaN-poisons every band verdict
`src/derive/storm.js:165-180`

`stormLagEffectiveKp` validates `r.time` but not `r.kp`; a single
null/undefined/"–" row makes `kpEffective` NaN → `lAuroralDb` NaN (the
`driver <= 0` guard passes NaN through) → every HF margin NaN → all bands go
dark. Sibling functions (`forecastKpPenaltyDb`, `bzForwardKpBump`) both check
`isFinite`; this one is the odd one out.
**Fix:** `if (!r || typeof r.time !== "string" || !isFinite(r.kp)) continue;`

### 3. Storm-phase classifier is time-swapped for deep storms
`src/derive/conditions.js:260-267`

For a CME storm with Dst min ≤ −50: during the *physical main phase* (Kp
rising, lag kernel not caught up) the classifier returns "active" (+2 dB);
during *recovery* (Kp down, kernel still elevated, Dst slow to recover) the
main check - whose condition is a superset of recovery's whenever Dst ≤ −50 -
returns "main" (+4 dB aurora amp), and the recovery-TID σ (+4 dB) is
unreachable. The +4 dB amplification and recovery σ regimes are systematically
applied at the wrong times. Comments at conditions.js:248-253 vs :1159 already
disagree about what "main" means.
**Fix:** test recovery before main (or exclude `kpEffective > kpNow + 0.5`
from the main condition).

### 4. WSPR foF2 inversion compares mismatched SNR references (−29 dB bias)
`src/physics/wspr-invert.js:147-190`, production path via `fuse.js:455`

The bisection inverts `snrMarginHf(...).margin` against raw observed WSPR SNR.
But `margin = SNR_pred − snrRequiredDb` with `snrRequiredDb = −29`, so margin
= predicted SNR **+29 dB**. Solving `margin ≈ snrObs` forces the predicted SNR
29 dB below what was observed - a systematic low bias on every inverted foF2
pseudo-observation feeding the fuse grid (many spots are instead dropped by
the range guard). The comment "same units wspr.live reports SNR in" is the
tell. Damage bounded by the 1.5 MHz error budget and [2,20] MHz clamp, but
structural.
**Fix:** invert against `snrObs − WSPR_SNR_REQ_DB` (i.e. `snrObs + 29`).

### 5. The entire NVIS branch is unreachable - 0–1500 km is not modeled
`src/derive/conditions.js:381-414` vs `src/derive/paths.js:157,199`

`nvisAvailable` requires `dKm < 1500`; the destination grid filters out every
cell with `dKm < 1500`. So the NVIS MUF blend, `hFNvis`, the "NVIS" label, and
the threaded `giroFoF2` are all dead, and regional 80/60/40 m propagation -
the bread-and-butter use case - has no verdict surface at all. The whitepaper
presents Eq. nvistail as active (also flagged as whitepaper item C14).
**Fix:** add short-range sample cells scored through an NVIS budget, or delete
the branch with a pointer to the planned NVIS surface. Don't leave it looking
live.

### 6. Tropo ingest: half-cell latitude misregistration at 0.25° resolution
`src/tropo/ingest.mjs:324-361`

Output cell centers sit at `−90 + step/2` offsets while GFS native latitudes
are exact multiples of 0.25°, so `Math.round((latMax − lat)/latStep)` lands
exactly on `k − 0.5` for every input row; JS rounds half toward +∞, so every
0.25° cell takes the value from ~14 km north of its labeled center, the −90°
row is dropped, and lon 179.75° is discarded instead of wrapped into col 0
(`ingest.mjs:362`; contrast `pack-binary.mjs:77` which wraps). At the default
0.5° this is masked only by GRIB stream order (last-write-wins).
**Fix:** bin by cell span (`Math.floor((latMax + latStep/2 − lat)/latStep)`)
or define the output grid on the native GFS lattice; wrap the date-line
column.

### 7. Tropo ingest: thin-layer gradient blow-up injects noise M-units
`src/tropo/ingest.mjs:469-477`

The synthesized ground level (`orog + 2` m) can sit metres below the first
pressure level when `sp` is fractionally above a member of `LEVELS_HPA`. The
super-refractive term and the convection flag both test *gradients* with no
minimum layer thickness: over a ~5 m layer, Float32-level noise (±0.004
M-units) reads as −156 N/km and can contribute ~78 M-units - nearly the whole
`CUT_DUCTING = 90` - or 0.1 K of noise reads as −12.5 K/km and spuriously
trips `lowAltConvective` (×0.2 suppression at :568).
**Fix:** enforce a minimum layer thickness (~30–50 m, matching
`deltaNFromRows`'s 100 m guard) and/or thickness-weight `superRefractiveSum`
(also fixes the resolution-dependence in Part 2, item T3).

### 8. Grid cells with no digisonde within 2500 km are never scored
`src/derive/paths.js:113-128`, `src/derive/conditions.js:697`

Station-less cells return `muf = null` and are skipped entirely, so large
ocean/southern-hemisphere sectors are invisible to the verdict, biasing
`openDirs`/breadth toward NA/EU/JP; hub anchors can snap to never-scored cells
and silently drop out of `hubMean`. Ironically both `mufConsensus` (climo leg)
and the global fuse grid could cover these cells - they're just never
consulted because `tryMargin` is never invoked.
**Fix:** let station-less cells through with `mufMHz: null` and fall back to
fuse/climatology; restrict hub snapping to scored cells.

### 9. Forecast-σ window: half the promised window is dead code
`src/derive/storm.js:135-136`

Rows are filtered to `dtH ∈ [0, 12]` (and the doc comment promises 6–12 h
coverage), but only `dtH <= 6` feeds `peakIn6h`; the 6–12 h half is collected
and discarded. The in-progress slot (started <3 h ago, spanning now) is also
skipped because slot *start* is compared, and `h1` is parsed but unused.

## Part 2 - Physics-questionable (defensible, but worth a look)

### Ionosphere engine

- **E1. Fixed M-factor `MUF = 3.0 × foF2`** (`climatology.js:296`,
  `wspr-invert.js:156`) and MUF(3000) products applied to all path lengths
  without an M(d)/M(3000) correction (`conditions.js:453`). For a 1500–2500 km
  single hop the oblique factor is ~2.0–2.6, so `effMuf` is overstated up to
  ~30% on exactly the short cells most likely to win "best path" - pushes
  10/12/15 m toward false-open. Live `giroHmF2` is already threaded for the
  hop ceiling; the same observation could drive the M-factor
  (`nvisSecantFactor`/`hopCeilingKm` geometry is already available).
- **E2. `takeoffAngleDeg` is flat-earth** `atan(2h/d)` (`geometry.js:96`). At
  the 4000 km hop ceiling it returns 8.5°; spherical geometry puts the true
  takeoff near 0–2°. This feeds `antennaGainAtElevation`, where 8.5° vs 2° on
  a low dipole is many dB, systematically in the DX-saturation regime. One-term
  curvature correction: `atan(2h/d − d/(4·R_E))`-family.
- **E3. `lEsScreenDb` is a hard 5 dB step** at foEs = 5 MHz and f = 2·foEs
  (`loss.js:267`) - the exact cliff family retired everywhere else (auroral Kp
  gate, hop boundary, flare twilight). Smooth both edges.
- **E4. `snrMarginHfEs` hard-nulls above Es MUF** (`snr.js:471`), cliffing from
  ~10 dB-of-loss to closed at the MUF edge and making `lMufDb`'s over-MUF
  branch unreachable there. The F2 budget deliberately allows smooth over-MUF
  operation; the Es budget contradicts it.
- **E5. `lHopGroundReflectionDb` hardcodes the H-pol Fresnel branch** even for
  `antType: "vertical"` (`loss.js:199`). V-pol sees several dB more per-bounce
  loss near the pseudo-Brewster angle. The H-pol calibration win was measured
  on the aggregate (H-pol-dominated) population; it's now specifically wrong
  for vertical users.
- **E6. Hop-count inconsistency:** `pathMinMuf` (`climatology.js:260`) and the
  scatter block (`conditions.js:514`) call `hopsForDistance(dKm)` without the
  live `hF` the SNR budget uses - MUF/scatter sampling and loss sampling
  disagree about hop geometry on elevated/depressed hmF2 days.
- **E7. Es fuse grid resolution vs coherence:** `computeFuseEsGrid` defaults to
  10° (~1100 km) cells while Es localization/coherence is 500 km - patches
  alias/dilute between grid nodes. Used in production (`conditions.js:289`).
  Build the Es grid finer (2–3°) or interpolate stations directly.
- **E8. Es-vs-F2 mode selection asymmetry** (`conditions.js:557-613`):
  gray-line/TEP/scatter bonuses are added to F2 *before* the comparison and
  dropped if Es wins; gray-line (a D-region refund) applies to the Es path
  too. Also the `eligible` test (:638) uses the F2 `effMuf` on Es-mode rows.
- **E9. Stale-but-parsable Kp history** (`storm.js:160-184`): if the history
  feed froze 24–48 h ago at Kp 2 while `kpNow` reads 8, the kernel returns ≈2
  and `kpNow` is ignored - storm response vanishes when it matters most.
  Append `kpNow` as a synthetic `dtH=0` sample, or floor on it when the
  freshest history sample is stale.
- **E10. Meteor showers ignore radiant visibility** (`showers.js:125-133`):
  Sydney gets "Perseids shower active" (radiant never rises at −34°S), and
  "building" phase passes the gate up to 30 days pre-peak while the note says
  "active". Store radiant declination; gate on visibility; name the shower
  only near peak.

### Tropo index

- **T1. Surface bonus / layer-inversion double-counting** (`ingest.mjs:510-548`):
  the surface bonus spans up to the first level >200 m AGL (typically ~320 m,
  covering layers i=0 and i=1), while `layerInversionSum` skips only i=0 - an
  inversion at 110–320 m scores in both, and can also arm the +25 `hpblBonus`
  (three terms, one inversion).
- **T2. Inversion thresholds are absolute kelvin over variable-thickness
  layers** (`ingest.mjs:511-539`): an isothermal (non-inverted) layer trips
  the 3 K cut once dh > ~460 m - routine above 850 hPa and guaranteed for the
  surface bonus over high terrain. Threshold on lapse-rate deviation (K/km)
  instead, or cap the surface-bonus dh.
- **T3. `superRefractiveSum` is vertical-resolution-dependent**: contribution
  is per layer, not per metre, so the index value is coupled to `LEVELS_HPA`
  and any future level-set change silently re-scales the marine carpet and
  invalidates the calibrated cuts. Thickness-weighting fixes this and bug #7.
- **T4. Three different "gradient layer" definitions** share
  `classifyGradient` thresholds: calibrate (strongest single sonde layer,
  10–100 m), ingest (110–850 m GFS layers), production handler
  (bulk surface→~1 km, the layer P.453's ΔN is actually defined on). The
  calibrate↔ingest pair is internally consistent (cuts were fit against it),
  but the handler and the map will disagree at the same location by
  construction. Also: calibrate silently accepts merge-leads envelope grids
  (max over two valid times) against instantaneous sondes - warn or refuse
  when `forecast_hour_envelope` is present.
- **T5. Moisture gate uses 2 m humidity for elevated inversions** - fine for
  the Antarctic problem it solved; consider gating layer inversions by `e` at
  the layer's base level (already computed as `eMbar`) for coastal-desert edge
  cases. Sea ice treated as open water (no ICEC field) is mostly self-limiting.

## Part 3 - Whitepaper: state and priority fixes

The paper (last touched 2026-05-12) predates five architectural changes and is
wrong at the formula level in several places. Full A/B/C/D tables from the
drift audit are preserved below; the priority order for a reader trying to
reproduce the shipped model:

1. **Basket**: 72 radial paths → ~400–500-cell 10°×10° destination grid,
   1500–18000 km (A1/A2; the paper also says "10-path basket" elsewhere - D1).
2. **Tier aggregation**: "best-margin path wins" → worldwide 14-hub mean with
   best-path fallback (A4), and the WSPR override semantics changed (A5–A7).
3. **MUF source**: kc2g × pure climatology → kc2g × **fuse grid**
   (GIRO + GIM-TEC + prior; `FUSE_PRIMARY_FOF2=true`) (A3, C2, C3).
4. **Gray-line**: 25 dB-capped `(1−cos^0.7)` midpoint form → 15 dB-capped
   Gaussian, path-integrated over 5 samples (A10).
5. **Tropo index**: the published formula omits the moisture gate (C1) and the
   calibration numbers are superseded (100%/17% → 71%/63%; cuts 5/90 → 20/90)
   (B1); heatmap smoothing/contours/isolines all changed (A21–A23).
6. **PCA retune**: 5 dB/decade·f^−1.5 → 9 dB/decade·f^−1.0 (A8/A9 - note the
   stale code comment at `loss.js:350-352` still says 5).
7. **Baseline provenance**: paper says human-reviewed offline artefacts; CI
   auto-commits daily at 06:00 UTC (A27/D6).
8. Smaller WRONGs: Es budget now includes L_aur (A20), σ_storm ramps from Kp 4
   (A24), EIA trough slope/cap retuned (A15), winter-anomaly gate 30° not 35°
   (A16), HSS window reversed (A17), stability passage still written in the
   reverted σ-percentile system (A26/D5), shower catalog mismatches (A25),
   localStorage key (A14), workflow filename (A32).
