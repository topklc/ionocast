## Part 1 - Bugs

### 1. BUG - `pathMinMuf`'s per-hop scale factor is mismatched with the fuse grid - FIXED

`src/physics/climatology.js:303` · `src/derive/conditions.js:449-466,478`

`pathMinMuf` re-prices every reflection point as

```
muf_k = 3.0 · climatology(p_k) · (mufMid / climoMufMid)
```

The correction scalar is only meaningful if `climoMufMid` is the **same
climatology function** evaluated at the midpoint - then the ratio collapses to
`muf_k = mufMid · climo(p_k)/climo(mid)`, which is what Eq. `pathmuf` in the
paper states and what the comment at `climatology.js:301-303` intends.

Since `FUSE_PRIMARY_FOF2` was flipped on, the caller no longer passed that.
`conditions.js:449` set `foF2c = fuseGrid.lookup(mid)` and `:466` passed
`climoMuf = foF2c · 3.0`, so the denominator was the **fused** midpoint value
while the numerator stayed **pure climatology**. The per-hop profile was
therefore scaled by `climo(mid)/fuse(mid)`, a factor with no physical meaning.

The two legs disagree for three independent reasons, so this is not an
edge case:

* near any digisonde the fuse cell is ~92 % observation (`invVar` 11.1 vs
  prior 1.0), and GIRO-vs-climatology RMSE is ~1.7 MHz on a ~6 MHz base;
* `computeFuseGrid` feeds its prior `f107Effective = 0.7·f107A + 0.3·f107`
  (`fuse.js:435`) while `pathMinMuf` calls `foF2Climatology(f107A, …)`;
* `computeFuseGrid` applies a storm depression of up to −3 MHz
  (`fuse.js:449`) that `pathMinMuf`'s internal call does not.

**The error was one-sided.** `minMuf` is seeded at `mufMidpoint` and only ever
decreases, so `fuse < climo` was silently clipped away while `fuse > climo`
depressed the path MUF. On odd hop counts the midpoint *is* a reflection
point, so the model discarded MUF at the very point carrying the observation.

Worked case (3-hop path, `mufMid` = 20 MHz, 20 m):

| climo(mid) | fuse(mid) | midpoint-hop MUF | f/MUF | ΔL_muf |
|---|---|---|---|---|
| 6.0 | 6.0 | 20.00 | 0.70 | 0 dB |
| 6.0 | 7.0 | 17.14 | 0.82 | **+1.7 dB** |
| 6.0 | 7.7 | 15.58 | 0.90 | **+4.7 dB** |
| 6.0 | 9.0 | 13.33 | 1.06 | **+18.6 dB** |

Applied to every path past the hop ceiling (~4000 km) - i.e. most of the DX
grid and most hub anchors - and biased only toward false-closed.

**Fixed** by splitting the two roles the one variable was serving.
`conditions.js` now computes `climoMufPure` (pure `foF2Climatology` at the
midpoint, ×3) alongside `climoMuf` (the fused second opinion), passes the
former to `pathMinMuf` and keeps the latter for `mufConsensus`. Observations
still reach the budget - through `mufMid`, which is where they belong. The
pure-climatology branch is unaffected (the two values are the same number
there by construction, and that branch now reuses the single evaluation).
The caller contract is documented at `climatology.js` above `pathMinMuf` so
this cannot silently regress again. Sampling the fuse grid per hop instead
would be a strict information gain but is a different change with its own
resolution trade-off - deferred to BACKLOG.md.

### 2. BUG - WSPR inversion emits clamp artefacts (2 / 20 MHz) as fuse observations - FIXED

`src/physics/wspr-invert.js:41-61,87` · production path `fuse.js:453-468` ·
input wired at `src/data/data-sources.js:144`

`snrMarginHf` depends on `foF2` **only** through `lMufDb(f, 3·foF2)`, and
`lMufDb` returns 0 for `f/MUF ≤ 0.70`. So the predictor `invertOneSpot`
bisects is *flat* for all `foF2 ≥ f/2.1` - 74 % of the [2, 20] MHz search
range on 20 m, 92 % on 40 m, and **the entire range on 80 m and 160 m**.

In the flat region the bisection has no root to find, and the loop's exit
paths did not notice:

* `snrObs` above the plateau by more than `tol` (0.5 dB) but within the +3 dB
  acceptance slack → every step took `lo = mid` → fell out of the 30
  iterations at `19.99999…`, which passed the `fo > 20` guard and was emitted
  as a **20 MHz foF2 observation**;
* symmetrically below → `2.00000…`, emitted as a **2 MHz observation**;
* inside `tol` → returned the arbitrary first midpoint, **11 MHz**.

Verified by simulation (`f = 7.04` MHz, offsets relative to the plateau):

```
SNR_obs = plateau +2.9 dB  ->  foF2 = 20.000000 MHz   <-- ceiling artefact
SNR_obs = plateau +1.0 dB  ->  foF2 = 20.000000 MHz   <-- ceiling artefact
SNR_obs = plateau +0.2 dB  ->  foF2 = 11.000000 MHz   <-- arbitrary midpoint
SNR_obs = plateau -1.0 dB  ->  foF2 =  2.984375 MHz   (genuine inversion)
```

These are cell-medianed and pushed into `buildFoF2Grid` with `invVar = 1/1.5²
= 0.444` against a prior weight of 1.0. A single 20 MHz artefact in an
observation-sparse cell drags that cell to `(1·climo + 0.444·20)/1.444` ≈
`0.69·climo + 6.15` - for a 6 MHz climatology that is **10.3 MHz**, a 70 %
foF2 inflation. It then compounded with finding 1 (inflated `fuse(mid)` is
exactly what depressed the per-hop MUF).

**Fixed** with three guards in `invertOneSpot`, replacing the ±3 dB slack
that was silently returning bracket endpoints:

1. **sensitivity** - require the bracket response `hi0 − lo0 > 2·tol`, so a
   spot whose band cannot constrain foF2 is dropped rather than inverted.
   This drops every 160 m / 80 m spot by construction, which is correct: they
   are below the MUF for any plausible foF2 and carry no foF2 information.
2. **bracketing** - require `lo0 < snrObs < hi0`, so a root provably exists
   strictly inside. Outside that range there is no solution, only a nearest
   endpoint.
3. **convergence** - return only a value that actually reproduces the
   observation to within `tol`, instead of returning the last midpoint
   unconditionally.

The caller's plausibility clamp is now epsilon-inclusive and keyed to the
same bracket `invertOneSpot` searched, so a solution pinned to an edge is
discarded even if a future predictor produces one. Post-fix behaviour is
re-verified in Part 5. The stale module header claiming this is not a
production path is corrected (D1), as is the uniqueness claim (D4).

### 3. BUG - `lAbsDiurnalDb` has a 4.4 dB cliff at the `cosZ = 0.05` night gate - FIXED

`src/physics/loss.js:171`

```js
if (cosZ == null || isNaN(cosZ) || cosZ < 0.05) return 0;
```

but the returned value at `cosZ = 0.05` is `dayLoss(f) · 0.05^0.7 =
0.123·dayLoss(f)`, not ~0. Measured step across the gate:

| band | f (MHz) | cosZ = 0.0499 | cosZ = 0.0500 | step |
|---|---|---|---|---|
| 160 m | 1.85 | 0 dB | 4.448 dB | **4.45 dB** |
| 80 m | 3.65 | 0 dB | 1.426 dB | 1.43 dB |
| 40 m | 7.10 | 0 dB | 0.425 dB | 0.43 dB |

This is the exact cliff family the codebase has systematically retired
(auroral Kp gate, CGM edge, hop boundary, Es screening, flare twilight). It was
also internally inconsistent twice over: `lFlareDb` (`loss.js:470`) already
ramps linearly over the *same* `cosZ ∈ [0, 0.05]` interval for the same
physical reason, and the paper states the term as the continuous
`L_day·(max(0,cosχ))^0.7` with the 0.05 cut mentioned only in prose
(`sec:labsd`).

It bit on 160/80 m within ~20 min of every terminator crossing - the same
geometry the gray-line bonus is designed for, so the two terms stepped
against each other.

**Fixed** with the same linear ramp `lFlareDb` uses over the same interval.
Provably calibration-neutral: values at `cosZ ≥ 0.05` are bit-identical
(verified across all ten HF bands over the whole sunlit range), so the basket
the term was fit against does not move; only the twilight sliver changes,
from a hard zero to a linear approach to zero.

## Part 2 - Physics-questionable

* **P1. Es screening used QTH foEs while Es-as-mode used the path midpoint -
  FIXED.** `conditions.js:284` put `foEs: foes` (a single value parsed off the
  VHF band table, i.e. near the QTH) into `bandOpts`, so `lEsScreenDb` in the
  F2 budget screened an 8000 km path on the operator's local Es, while two
  lines later the Es-mode budget correctly used `foesPath` from
  `fuseEsGrid.lookup(mid)`. Same physical quantity, two different samples, in
  the same band evaluation. `foesPath` is now resolved once, before the F2
  budget, and both consumers read it. Side effect, in the right direction:
  cells with no Es observation in range now read the grid's 1.0 MHz floor
  instead of a possibly-strong QTH value, so spurious screening of paths far
  from any Es observation goes away.

* **P2. Legacy no-geometry branch skipped the path caps - FIXED.**
  `snr.js:342-345` computed `lAbsD = nHops · lAbsDiurnalDb(...)` and
  `lAur = nHops · lAuroralDb(...)` but, unlike the `pathIonoLosses` branch it
  is documented as being cardinality-consistent with, never applied
  `PATH_ABSD_CAP_DB` / `PATH_AUR_CAP_DB`. Now clamped to the same ceilings.
  No production input reaches the caps on this branch (the only caller that
  hits it is the local-MUF fallback, where `nHops` is 1), so this is a
  consistency fix, not a numbers change.

* **P3. Hop geometry is not actually shared between the MUF/antenna sampler
  and the loss sampler - DOCUMENTED, deferred.** `takeoffAngleDeg` and
  `mufObliqueFactor` use `d_hop = min(d, ceiling)`, while `pathIonoLosses`
  lays reflection points out on the integer-bracketed `floor/ceil(nC)`
  geometry. On a 6000 km path that is 4000 km "hops" (elevation floored at
  3.0°) versus the loss sampler's two 3000 km hops (4.27°). The paper claims
  the shared `_hopElevationRad` helper means the two "can never disagree
  about hop geometry" (`sec:mufoblique`) - true between those two consumers,
  not against `pathIonoLosses`. The scope of the guarantee is now stated
  precisely in `geometry.js`. Reconciling the code shifts `gAnt` on every
  multi-hop path, so it is a calibration change and is deferred to BACKLOG.

* **P4. `mufConsensus`'s two legs are no longer independent - DOCUMENTED.**
  `sqrt(k·c)` blends kc2g against the fuse grid, but kc2g's `mufd` is itself a
  digisonde-assimilated map and fuse's dominant observation source is the
  same GIRO station set. The "second opinion" is largely the same measurement
  twice; `divergence` correspondingly under-reports real disagreement. The
  symmetric-blend rationale in `climatology.js` was written when the second
  leg was pure P.1239, so it now carries an explicit independence caveat.
  Behaviour unchanged - narrowing the blend is a calibration decision.

* **P5. Gray-line credit on the night side - NOT a bug, deferred to
  calibration.** The paper (`sec:grayline`) explicitly answers the "refunds a
  charge never made" objection and re-bases the term as a credit relative to
  a fully-dark path (terminator tilt / ducting / antipodal focusing), with
  `L_day(f)` as a magnitude anchor rather than a derivation. Left alone.
  Recorded in BACKLOG for one calibration look, because it is the largest
  additive term in the budget and sits where tier boundaries are most
  sensitive: at `cosZ = 0` on 160 m the model charges 0 dB absorption and
  pays +15.0 dB, and at `cosZ = −0.05` it still pays +14.4 dB - i.e. it
  asserts a terminator path is two full tier boundaries better than the same
  path at midnight. Note finding 3's ramp now charges up to 4.45 dB in the
  sliver where this credit peaks, so any re-fit must postdate it.

## Part 5 - Re-audit of the fixes

Second pass over the diff itself, treating it as unreviewed code.

### Behaviour re-verified against the original probes

* **Finding 3.** Max step over `cosZ ∈ [0, 0.2]` sampled at 1e-4: **0.0151 dB**
  on 160 m (was 4.45 dB at the gate), 0.0049 on 80 m, 0.0014 on 40 m - the
  residual is the sampling step on a now-continuous curve. Difference from
  the old function anywhere in `cosZ ≥ 0.05`, across all ten HF bands:
  **exactly 0.0 dB**, so the calibrated regime is untouched.
* **Finding 2.** All ceiling/floor artefacts now dropped on 80/40/30/20 m;
  every 80 m spot dropped (correct - zero response range); genuine interior
  inversions still land and reproduce the observation (20 m: targets −45 …
  −1 dB invert to 2.42 … 5.94 MHz, each reproducing its target within `tol`).
* **Finding 1.** With the pure-climatology denominator restored, the midpoint
  hop reproduces `MUF_mid` exactly (20.0000 == 20.0000), so `pathMinMuf` is
  again a pure shape correction and the path MUF is set by the genuinely
  weakest hop (17.33 MHz from a 5.2 MHz climatology hop) rather than by a
  climo/fuse ratio artefact (which gave 14.86 / 11.56 MHz for the same path).

### Defects found in the fix, and closed

* **Reserved-word-adjacent naming.** The convergence guard originally used
  `var final`. Legal in ES modules (`final` is not a strict-mode reserved
  word) but a legacy future-reserved word and confusing. Renamed `settled`.
* **Const landed inside a doc block.** `EDGE_EPS_MHZ` was inserted between
  `wsprSpotsToObservations`'s doc comment and its signature, orphaning the
  comment. Moved above the block.
* **Duplicate climatology evaluation.** The first cut of the finding-1 fix
  called `foF2Climatology` twice at the same midpoint on the
  pure-climatology branch. Restructured so the single evaluation serves both
  the `pathMinMuf` denominator and that branch's second opinion.
* **Residual sharp edge in guard 1.** With a bracket response between one and
  two tolerances, the first bisection midpoint already sits within `tol` of
  any admissible observation, so the loop would have returned the arbitrary
  bracket centre (11 MHz) and called it a solution. Threshold raised from
  `tol` to `2·tol`. No amateur band lands in that window - the response is
  `lMufDb(f, 3·minFoF2)`: 0 dB at 80 m, 4.1 at 60 m, 25 at 40 m, 52 at 20 m,
  and `f ∈ (4.60, 4.77)` MHz would be needed to hit the gap - so this costs
  nothing today and guards a future caller that narrows the bracket.
